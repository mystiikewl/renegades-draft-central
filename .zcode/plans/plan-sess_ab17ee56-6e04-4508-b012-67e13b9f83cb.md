# Renegades Draft Central — Complete 2026 Rebuild

**Outcome:** Same Supabase project, same signed-up users (auth.users untouched), brand-new season-aware schema, ESPN/NBA live data pipeline, and a from-scratch frontend. 2025 draft results preserved as a read-only archived season.

1. **Archive 2025 data**: `pg_dump` the public schema → `archive/2025-season-dump.sql` (committed to repo).
2. **Export auth users** (uid + email list) → `archive/2025-users.csv` for mapping into the new profiles table.

4. **Kill the unauthenticated surface**: disable `invite-user` / `admin-actions` edge functions until rebuilt with JWT verification.

## Phase 1 — Fresh database schema (single clean baseline)

Drop the entire `public` schema (auth schema untouched). Rebuild as **one reviewed migration set** in `supabase/migrations/` (old migrations moved to `supabase/migrations-archive-2025/` for reference).

**Core model — seasons as first-class citizens:**

- `seasons` — `id`, `label` ('2025-26', '2026-27'), `status` (`archived` | `pre_draft` | `live` | `complete`)
- `profiles` — `id = auth.uid()` (fixing the old id/user_id confusion), `is_admin`, `team_id`; self-UPDATE restricted from `is_admin` via column privileges
- `teams` — one row per franchise, stable across seasons (`owner_profile_id`)
- `players` — static bio only: ESPN player id (natural key for imports), name, position, team, image
- `player_seasons` — stats per (player, season); populated by the import pipeline
- `rosters` — **the single source of drafted truth**: (season, team, player, acquisition: `draft`|`keeper`, acquired_at). Kills the old 3-way split (players.is_drafted / draft_picks / keepers)
- `draft_settings` — per season: order, rounds, snake flag, `pick_time_limit_seconds`, status (`paused`|`running`|`complete`)
- `draft_picks` — (season, round, pick_number, team_id, player_id nullable, is_used) — the board/slots only, not the truth
- `user_favourites` — (profile, player, season)

**Server-authoritative draft logic (SECURITY DEFINER RPCs with `is_admin` checks inside):**
- `make_pick(season, player_id)` — validates turn, pick slot, availability, and writes draft_picks + rosters in one transaction
- `undo_last_pick(season)` — team-scoped window or admin
- `pause_draft` / `resume_draft` / `reset_draft` — admin-only
- `set_draft_order`, `trade_picks`, keeper assignment — admin-only RPCs (no direct client table writes anywhere)

**RLS done right:** no `auth.role()='authenticated'` write policies; no hardcoded emails; drafts/rosters readable by all league members, writable only via RPCs; profiles self-update column-restricted.

## Phase 2 — ESPN/NBA data pipeline

Rewrite `scripts/import-players.js` as an idempotent importer (no hardcoded keys — env vars):

- **Player bio + stats**: ESPN NBA API (`sports.core.api.espn.com`) as primary source, keyed on ESPN player id → upsert `players` + `player_seasons`
- **ESPN fantasy league stats** (the Hashtag Basketball pattern): pull league data from ESPN's fantasy API (`lm-api-read.espn.com`) using league id + optional SWID/ESPN_S2 cookies stored in env — pulls real league rosters/scoring if desired
- Runs as `scripts/import-nba.ts` locally + optionally a scheduled Supabase edge function pre-season

## Phase 3 — 2025 archive import

One-time `scripts/import-2025-archive.ts`: reads `archive/2025-season-dump.sql` data, maps old tables → new schema (`seasons` row '2025-26' status `archived`, old draft_picks + keepers → `rosters`, player stats → `player_seasons`). Re-link users via `archive/2025-users.csv`. Result: 2025 viewable read-only in-app under the new model.

## Phase 4 — Full frontend rewrite (new `src/`, old code kept at `legacy/` until parity)

**Stack:** Vite + React 19 + TypeScript, **TanStack Router** (typed, declarative guards) + **TanStack Query v5** (single data layer — no raw supabase calls outside `src/api/`), **Tailwind v4 + shadcn/ui**, Zustand for draft-day UI state (clock, tab state), Supabase realtime via **one** subscription abstraction that invalidates Query cache (replacing the 5 overlapping hooks).

**Build order (draft-day-critical first):**
1. `src/api/` — typed service layer over new schema + RPCs; generated Supabase types as the single type source
2. **Draft page, mobile-first**: board (responsive snake grid), visible pick clock w/ pause, on-the-clock banner with working CTA, team-scoped pick controls, undo, offline queue + ErrorBoundary on the draft route
3. Onboarding: invite links with team tokens (no admin-assigned-only flow), claim team, configurable keeper step
4. Admin: draft order (drag-drop), pick trading, rollback/reset — all via RPCs, real confirm dialogs
5. Rosters, player pool + favourites, league analysis (rebuilt on real `player_seasons` data)
6. Tests from day one: pick flow (happy + conflict + wrong turn), undo, admin ops — the gaps that hurt in 2025

**Explicitly not carried over:** ~30 unused shadcn components, `mockData.ts`, `draftTabService` layer, dual toast/responsive systems, root `integrations/` dir, Lovable meta tags/comments, `DraftTabs-refactored` — old `src/` moves to `legacy/` and is deleted once parity is confirmed.

## Phase 5 — Cutover checklist

- All 2025 users can log in and see their profile/team mapped
- 2025 archived season viewable; 2026 season creatable via admin
- Import pipeline run for 2026-27; draft simulation test end-to-end (make pick, wrong-turn rejection, undo, pause, trade)
- Netlify deploy from this branch

## Sequencing rationale

Schema before frontend (the API layer's shape depends on it), archive import before new-season setup (same mapping code), draft page before secondary pages (it's the reason the app exists and where 2025 hurt most). Security fixes happen first so nothing is exposed while we work.
